# 测试与上线验收

自动检查结果应以 GitHub Actions 对应提交为准；失败的提交不能视为已验收版本。

## 自动测试

- 核心：XLSX 往返、字段级原值比较、真正冲突、清空选择、重复/未知标识、识别列修改、缺失型号数量、整行排序、纯文本公式前缀、错误日期、图片锚点、标准筛选表、外部链接、宏、XML实体与压缩限制。
- Odoo 19 合成契约：安装及视图校验、单工厂隔离、四字段预览/保存、重复导入、服务端单独修改、旧预览、篡改显示值/文件、其他用户、私有快照、过期会话、取消行、任务日期精确同步、重复任务、权限撤销。
- 静态检查：Ruff、Bandit；依赖漏洞：pip-audit。它们不构成无漏洞保证。

V2 增加：10 列顺序、只读产品描述的来源优先级、四个黄色可编辑字段映射、旧版导入与批次布局绑定、同型号不同颜色记录排序后的精确回填、正式离线批次的可信管理员登记与完整往返。默认 100 pt 行高，长描述自动加高。

## 必须由 IT 在实际自定义模块测试环境完成

- [ ] 安装/升级使用与正式环境一致的 Odoo 19 和全部相关公司模块；确认没有测试替身模块。
- [ ] 两种导出范围，含空型号/数量、取消行、长要求、缺图和多工厂。
- [ ] 真实身份对应正确，跨单/跨公司/越权请求被拒绝。
- [ ] 四字段各自更新、明确清空、旧文件冲突、重复导入、再次导出显示正确。
- [ ] 原始状态、负责人、其他样品行、无关任务不被修改；无额外邮件、活动或外部调用。
- [ ] 已部署 Python overrides 和自动化与递归保护兼容；已知两个旧动作的窄范围保护有效。
- [ ] 两个真实会话同时预览/确认：冲突被拒绝或要求重预览，没有丢失更新。
- [ ] 中途异常时整次事务撤销，预览可重新生成。
- [ ] Excel 中修改、完整表排序、保存并导入；图片/行标识正确移动。
- [ ] WPS 中完成同样操作，隐藏标识页及标准表结构保留。
- [ ] 执行备份/恢复演练。代码回退与数据恢复分别验证。
